================================================================
A. 顶层结构
================================================================
return setmetatable(<VM大表>, {}):eW()(...)

  eW() = 入口:
    1) 立即执行反调试序言 (jq1ge, 见 E 节)
    2) b:g() -> (true, 4, nil...)  => 初始 vN=4, C[8]=0
    3) 循环调用 b:Ww -> b:gX 分发器 (控制流平坦化状态机)
    4) 状态机最终经 kF 返回 C[7] (包装好的内层虚拟机闭包)
    5) 顶层 (...) 立即调用该闭包 => 执行内层字节码

================================================================
B. 外层状态机 gX (控制流平坦化)
================================================================
- 对 vN 做二叉判定树 (if vN<=K then ... else ...), 共 230 个状态
- 每个叶子: 恒真/恒假谓词 (vN-vN==0, vN*vN>=0, vN%2==0 or vN%2~=0 及其 not)
  包裹一条真实跳转  => 纯语法噪音, 实际路径唯一确定
- ~60 个处理函数只做 "寄存器洗牌" (return N, C, <参数置换>), 无副作用
- 静态模拟得到的真实执行序列 (从 vN=4 出发, 共 50 步):

  4:pR  12:Cz  15:Kq  18:TV  19:fe  20:eG      <- 解密 5 段字符串
  22:Se 24:XK 25:wM 27:UN 28:De 30:zN 31:WX 34:TH 35:Vu 44:r
  47:Ro 48:yz 49:Mo 52:Vd 55:gc 57:NB 58:ke 62:Nm 66:mu 68:dR
  69:LL 71:Aw 75:VN 77:rj 79:GR 81:ww 85:nK 86:LF 89:pl 91:FR
  92:VW 94:cI 95:Qt 97:vH 98:Yp 100:OA 102:ZW 103:_
  223:vO  225:b[13]  226:MI  227:ya  229:Yz  232:kF -> 返回 C[7]

  副作用节点:
   pR  : C[8] = (C[8]*31 + 16993) mod 2^32          (=16993, 校验基准)
   Cz  : 解 [16][1..11]  -> C[1] (41B)   \
   Kq  : 解 [16][12..22] -> C[2] (41B)    |  每段调用一次 b[51] PRNG
   TV  : 解 [16][23..32] -> C[3] (40B)    |  XOR 密钥 (kv+i) mod 256
   fe  : 解 [16][33..42] -> C[4] (40B)    |
   eG  : 解 [16][43..52] -> C[5] (40B)   /
   b[13]: 定义 dx(内层VM装载器+解释器), C[6]=dx
   MI  : E=function(...) return C[6](C[1]..C[2]..C[3]..C[4]..C[5]) end
         C[7]=function(...) return b[77](b,E,...) end   (b[77]=调用器)
   ya  : C[9] = sum(bytes(C[1..5]));  并做反挂钩检查
         (debug.info(error|loadstring|load,"s") 必须返回 "[C]",
          否则 while true do end 死循环)
   Yz  : 要求 C[9]==C[8] (=16993), 否则死循环; 满足则转 232
   kF  : vN>=232 -> return 2, C[7]

【PRNG [51]】 状态存于 b[22]=124835273, 每次调用推进 3 步 (均 mod 2^28):
   x = (x*414251 + 29440879) % 2^28
   x = (x*933843 + 97174573) % 2^28
   x = (x*526153 + 214486619) % 2^28  -> 返回并保存
【字符串密文表 [16]】52 个 32 位字; 取字方式:
   w = (T16[i] - (2798128065 + i*308315633)) mod 2^32, 小端展开为 4 字节
【验证】解密出的 5 段共 202 字节, 字节和 = 16993 == C[8] (自洽校验通过)

================================================================
C. 内层虚拟机 (dx / jo / cS, 全部在 [13] 内部定义)
================================================================
字节码容器格式 (对 C[1]..C[5] 拼接后的 202 字节):
 1) M():  Y-转义还原 (YF2pQ->"  Y9dUk->'  YEPED->%  YqKls->空格
          Ym75y->$  YOiTX->!  YQHFh->~  Y62CR->#  Ybt7z->}  Y1nQc->&)
          然后 base-94 解码 (5 字符 -> 4 字节, 字母表=94 项的 I 表)
          前 4 字节小端 = 长度 (113)
 2) jo(): 流密码  uV=(61075230+(chunk-1)*204281080) mod 2^28
          每字节  uV=(816355*uV+12229739) mod 2^28; b=(b-uV%256)%256
 3) 分段结构 (6 段, 标签 118=头/221=密钥种子/237=upvalue源/
          86=常量块/82=寄存器映射/230=填充, 其余=指令流)
    - 整数全部为 7 位小端 varint (最高位=续行标志, 32 位有符号回绕)
    - 指令流: W(操作码, 原始字节) + SA/SB/SC/SD 四条 varint 操作数流
      (struct-of-arrays; 校验和 = 四流所有 varint 之和 mod 2^32,
       必须等于硬编码的 411152, 否则死循环)   <-- 实测: 411152 匹配!
 4) 常量块: 类型字节【明文】 0=nil 1=bool 3=string 其他=浮点;
    负载字节用 LCG (m=(547675*m+175655243) mod 2^28, 种子=221段) 逐字节解;
    字符串长度 2 字节明文小端; 浮点 = Pq * 2^(floor(MT/2)-2048), MT 奇数取负
    消耗字节数必须恰好等于块长, 否则死循环
 5) 运行时自修改: K[1].W[6] = (245+53)%256 = 42
    (静态字节码第 6 条指令为 14, 运行时被改写为 42 —— 两者都是垃圾指令)

E. 虚拟机指令集 (全部 43 条, 从 Rk/kP 解码出的真实 Lua 处理函数)
================================================================
外部处理表 OJ 共 39 个 (字节码操作码 0..42 去掉 15/19/23/31),
解码方式: base-94(Rk 块) 后按  LCG(uw=(152091*uw+119909739) mod 2^28,
种子 uw=(194014965+opcode*120221117) mod 2^28) 逐字节减密 ->
loadstring(sub(src,1,len))()  即: 操作码处理函数以加密 Lua 源码分发!

  00 EQ      V[a]=(V[b]==V[c]) 含 __eq 元方法
  01 LISTSET t=V[a]; n=V[b]; t[n+1]=V[c]; V[b]=n+1
  02 NEWTAB  V[a]={}
  03 LT      V[a]=(V[b]<V[c])
  04 IDIV    V[a]=floor(V[b]/V[c])
  05 JMPF    if not V[a] then -> b
  06 VARCNT  V[a]=vargc
  07 NOT     V[a]=not V[b]
  08 MUL     09 GE     10 MOV     11 NEQ
  12 SETUPS  ups[a].v[ups[a].i]=V[b]
  13 POW
  14 JUNK    local _=a*c+b          <- 垃圾指令(反静态)
  16 RETURN  按 S 映射收集返回值; b=255 时走可变返回
  17 GETGLOBAL V[a]=G[C[b]]
  18 MOD
  20 GETUPS  V[a]=ups[b].v[ups[b].i]
  21 APPVARG 把 vargs 追加进表
  22 NIL     V[S[a+i]]=nil (i=1..b)
  24 LOADSTR 短字符串直接编码在 4 个操作数里 (63371*a+41221 mod 65536 去扰)
  25 SETTAB  V[a][V[b]]=V[c] 含 __newindex
  26 JMPT    if V[a] then -> b
  27 GT
  28 CLOSURE V[a]=makefn(b+1,...)   (原型经 upvalue 编码: >=49152 父级up,
             >=32768 捕获父函数局部, 其余=全局名索引)
  29 JMP     -> b
  30 UNM     32 GETTAB  33 PACKVARG  34 DIV  35 LEN  36 LE
  37 LOADK   V[a]=C[b]
  38 SUB     39 CONCAT  40 ADD
  41 SETGLOBAL G[C[b]]=V[a]
  42 JUNK    local _=a*c+b          <- 垃圾指令(运行时 patch 目标)

内联处理 (cS 中直接实现, 全部是 CALL 家族, 经 V 置换表定位):
  字节19 = V[40] CALL 多返回值(支持 vararg 尾缀)
  字节15 = V[27] CALL 并把结果追加到列表 (t[n+i]=rets; n+=#rets)
  字节23 = V[29] CALL 固定返回值个数
  字节31 = V[39] CALL 并把返回个数写回寄存器
V 置换表: V[t]=(iw值-(22147+t*47252) mod 65536) mod 256, 42 对
  (V[40]=19, V[27]=15, V[29]=23, V[39]=31 —— 与 OJ 缺失的键完全吻合)

错误信息伪装: 处理函数使用 "attempt to perform arithmetic on a X value"
等标准 Lua 报错文案 (u 表 29 项), 让运行时表现与原生一致。

F. 反调试 / 反篡改清单
================================================================
F1 eW 序言 (启动前一次性执行, 任一失败 -> (nil)[1] 崩溃或挂起):
   - type() 检查: type/pcall/xpcall/error/rawget/rawset/getmetatable/
     setmetatable 必须都是 "function"
   - getfenv(0) 必须是 table; print 必须是 function; warn 缺省或 function
   - 全局一致性: env.print==print, env.warn==warn (检测全局被替换)
   - rawset/rawget 往返测试 (键 -271823); rawset 置 nil 后必须消失
   - pcall(error) 必须成功 (error 必须可正常调用)
   - table.create({},0,64) 必须成功
   - debug.info 指纹:
       debug.info(fn,"l") 必须返回行号(数字)
       debug.info(fn,"s") 必须返回 "string" 且 ~= "[C]"
       xpcall 错误处理器用 ":(%d+):" 从 traceback 提取行号,
       必须与 debug.info 的行号一致 (检测被调试器/挂钩篡改的调试库)
       debug.info(error,"s") 必须 == "[C]"
       rawget(_G,"loadstring") / rawget(_G,"load") 的 "s" 信息必须 "[C]"
       (检测用 Lua 重实现/沙箱替换的 load 系函数)
   - 蜜罐对象: newproxy 用户数据 + 3 个带毒元表 (__tostring/__concat/
     __call/__iter 一旦触发即置标志并崩溃) 的表, 哨兵串:
     "tddxhpfcpi", "lsphhfstdm", "vymgglkhqr"; 全部存引用防 GC
   - 崩溃原语: repeat/until + _ENV={error=error} 后 (nil)[1]

F2 dx 装载器内:
   - pcall(debug.info(loadstring,"s")) 必须返回 "[C]", 否则死循环
   - 字节码校验和必须 == 411152 (NU 表), 否则死循环
   - 常量块必须被完全消耗 (Zk==a+nC), 否则死循环
   - 所有死循环陷阱均为 `while true do end` (挂起而非报错, 拖死分析者)

F3 外层状态机:
