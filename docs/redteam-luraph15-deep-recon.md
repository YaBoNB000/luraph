## 结论先行

真解到 CPS 层被挡住。共撞上 **4 堵墙**，其中 1 堵是我们还没有、且对
「Roblox 执行器」场景正好对症的防御：

| # | 墙 | 性质 | 我方现状 |
|---|---|---|---|
| 1 | **环境绑定**：解释器原语表内嵌 Roblox API（`Vector3.new`/`Vector2.new`/`task.*`），离开 Roblox 连模块表都构造不了 | 真防御（可学） | **没有**，可学 |
| 2 | **Luau CLI 全局表只读**：`_G`/`getfenv(0)` 全只读，无法桩环境/挂钩子做动态分析 | 环境特性（非样本防御，但帮了它） | 我方输出同样受益 |
| 3 | **CPS 分散解码**：外层剥掉后载荷熵 6.4/8，解码逻辑散布 ~150 个微 handler + 穿线 LCG 态，无单一解码例程可提取 | 真防御 | **已有**（⑲⑳） |
| 4 | **敏感字符串拼名**：全文**零** `loadstring`/`debug` 字面量，全靠运行时拼名（`string.char` 仅 1 处，拼名表打散在解码管线里，连 `cancel` 都搜不到字符码） | 真防御 | **已有**（P4 同款，确认真 Luraph 也用） |

## 1. 逐层解的过程与撞墙点（多方法实测）

试了 5 种方法，逐一撞墙：

| 方法 | 结果 |
|---|---|
| M1 直接 `luau` 运行 | 撞墙 #1：`index nil with 'new'`（Vector3 是 nil） |
| M2 桩全局环境 | 撞墙 #2：`_G`/`getfenv(0)` 只读，桩不进去 |
| M3 源码级桩（替换 `Vector3.new`/`Vector2.new` 为桩函数） | 进一步撞 `index nil with 'cancel'`——`task.*` 一类**运行时拼名**访问，静态桩不掉 |
| M4 静态解外层载体 | ✅ 成功（见下），但到 CPS 层撞墙 #3 |
| M5 `luau-compile` 语法编译 | ✅ 通过——坐实障碍全在**运行时环境**，非语法 |

### 层 0：直接运行 → 撞墙 #1（环境绑定）
`luau l15.lua` 直接报 `attempt to index nil with 'new'`——模块表原语槽
引用 `Vector3.new`，CLI 里 `Vector3` 是 nil。把 `Vector3.new`/`Vector2.new`
在源码里替换成桩函数后再跑，又报 `attempt to index nil with 'cancel'`
（`task.*` 一类运行时对象，且**字段名是运行时拼出来的**——全文搜不到
`cancel` 的字符码 99,97,110,99,101,108，它是解码管线运行时才拼出来的，
静态桩不掉）。→ **样本把 Roblox API 嵌进解释器自身、且关键引用连名字都
运行时拼，离开 Roblox 连模块表都建不起来、也没法桩。**

### 层 0.5：想桩环境 → 撞墙 #2（只读全局）
想在 CLI 桩 `Vector3`/`task` 等全局：`_G.x=1`、`getfenv(0).x=2` 全部
`attempt to modify a readonly table`。**CLI 全局环境完全只读**，既桩不了
Roblox API，也钩不了任何全局函数。动态分析在 CLI 里被环境本身封死。

### 层 1：外层载体（静态可解）
`RC` = `[=[...]...]` 长串（体 52,606 B），前 4 字节 `LPH:` 水印。
`b[118](b[93](b.RC,5), b.XC, b.pC)` = `gsub(sub(RC,5), "[ -'}~]", pC)`：
10 个特殊字符（空格 `! " # $ % & ' } ~`）各映射成一个 5 字符令牌
（`"→=W8+C` 等）。纯确定性变换，已用 Python 复现，产出 52,602 B 缓冲。

### 层 2：CPS 解码 → 撞墙 #3
外层剥完的缓冲**熵 6.407 bits/byte、85 种字符**——仍是编码态，不是字节码
明文。这一层由 ~150 个微 handler 组成的 CPS 状态机（`OY` 二分调度 +
`kD/ww/No…` 子函数）用穿线 LCG(213,225) 逐字节 `bxor` 解开。**没有单一
解码例程可整体提取**，必须完整模拟该状态机（含 LCG 态穿线、跨函数状态
传递）才能继续。这就是 R006 攻击方自评「3~6 倍代价」的那堵墙，本轮实证。

## 2. 可学习的防御：环境绑定（墙 #1）

真实 v15 把目标运行时（Roblox）的 API 嵌进**解释器自身的原语表**，使产物
**只在目标运行时可运行、在通用沙箱里连构造都失败**。效果：
- 攻击方的通用沙箱（如 Luau CLI / 无 Roblox 的模拟器）根本跑不起来，
  动态分析（运行→dump→hook）从入口就被掐断；
- 这与我们 ⑱（已弃用）的「变长参递送激活」不同：环境绑定**不需要用户
  传任何东西**，天然满足「混淆后直接可运行」，只要跑在目标运行时里。

**对我方的意义**：我们的产品主打 Roblox 执行器，这条防御**正好对症**——
它能在「攻击者的分析沙箱 ≠ 目标执行器」时，从入口阻断动态脱壳，且保留了
用户要的「直接可运行」。这与 R007 的教训互补：R007 攻击方靠「干净运行 +
转储」得手，而环境绑定恰好让「干净运行」只在目标执行器里成立。

### 落地的现实约束（必须正视）
- **与 CLI 测试冲突**：一旦把产物绑定到 Roblox API，我们自己的 `luau`
  CLI 测试矩阵也跑不起来（只能 `luau-compile` 语法校验，跑不动运行等价）。
  → 只能做成**可选开关**（如 `--bind-env roblox`），绑定态产物仅语法校验 +
  专门的桩测试，不进通用运行等价矩阵。
- **绑定强度取决于「分析沙箱缺什么」**：绑定到 `Vector3`/`task` 这类
  Roblox 独有对象，通用沙箱缺 → 有效；若攻击方也搭了 Roblox 环境，则失效。
  故它是「抬高动态分析门槛」，不是绝对防线。

## 3.5 原语表全貌（环境绑定的量化实证）

从模块表抽出 **51 个原语槽**，把 Luau/Roblox 运行时几乎整套嵌入解释器：

| 族 | 数量 | 成员 |
|---|---|---|
| `buffer.*` | 16 | fill/len/create/copy/tostring/fromstring + read u8/u16/u32/i16/i32/f32/f64/readstring + write u8/u32/i8 |
| `string.*` | 12 | sub/byte/char/rep/find/match/gmatch/gsub/format/pack/unpack/insert |
| `coroutine.*` | 8 | create/resume/yield/wrap/status/running/close/isyieldable |
| `bit32.*` | 7 | bxor/band/bor/bnot/lshift/rshift/countrz |
| `table.*` | 6 | pack/create/concat/insert/move/… |
| Roblox 值构造 | 3 | `Vector3.new`/`Vector2.new`/`vector.create` |

要点：
- **`buffer.*`（16 个）是 CPS 解码的载体**——解码器用 `buffer.readu8` 读、
  `buffer.writeu8` 写，字节级解码跑在 Luau buffer 上（这也解释了墙 #3 为
  何难静态复现：解码状态在 buffer 里流转）。
- **无任何计时函数字面量**（`os.clock`/`tick`/`os.time` 全无）——真 v15
  **不用时间陷阱**（我方 L7 反而比它多这一层）。
- **`coroutine.*` 8 个全在**：既是被保护程序可用的原语，也进一步锁死
  「这是 Roblox/Luau 解释器」的环境绑定。

## 3. 与我方产品的对照（再确认）

- **墙 #3（CPS 分散解码）我方已有**：⑲⑳ 的去中心化尾链 + 加密碎片 +
  多层编码，与真实 v15 同构甚至更密（我方解释器/解析器全入密，真实 v15
  的微 handler 是明文函数、只是调度复杂）。
- **墙 #2（只读全局）我方输出同样受益**：我方产物在只读全局的沙箱里，
  攻击方同样钩不了全局函数。
- **墙 #4（敏感串拼名）我方已有**：P4 防御代码隐藏同款，本轮确认真
  Luraph 也在用（全文零 `loadstring`/`debug` 字面量）。
- **墙 #1（环境绑定）我方没有**：这是本轮唯一值得引入的新防御，且对
  Roblox 执行器场景对症。

## 4. 建议

1. **新增可选环境绑定**（`--bind-env <roblox|...>`）：把目标运行时独有
   API 的存在性/行为折进引导钥匙（缺失/桩化 → 引导层解出垃圾），实现
   「只在目标执行器可运行、通用沙箱解不动」。绑定态产物走独立测试通道
   （语法校验 + 桩环境冒烟），不进通用运行等价矩阵。
2. 维持 ⑲⑳ 结构防护（已与真实 v15 持平偏强），环境绑定作为其上的
   「运行环境门禁」，二者叠加 = 结构 + 环境双门。
