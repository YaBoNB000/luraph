# 「看着像 + 安全性也像」总计划（学结构，不抄结构）

> 2026-09-05 立项。用户目标：**看着像**（轮廓、气味与 Luraph v15 同族）、
> **安全性也像**（攻击成本同量级）；**学结构不是一比一抄**——指纹从
> 「逐条对黄金数」降级为「轮廓带 + 安全项」，给安全改造让路。
> 同期用户指出三个致命缺点（本计划的直接驱动）：
> ① 虚拟机解释器完全明文暴露；② 字节码结构过于规整；③ 常量没做
> 动态内联/加密。

---

## 0. 现状事实核对（攻击链侦察结论）

当前 v15 输出对静态分析者是**自描述**的——复原整个 VM 不需要运行程序：

| 可见物 | 位置 | 攻击者拿到后能做什么 |
|---|---|---|
| 解释器全部逻辑 | 经 junk+mangle 后以**代码**嵌进脚手架 dh 数字槽跑者（strings/numbers/body/flatten 全关） | 直接读懂 fetch/dispatch/parse/载体解码；控制流未扁平化，逐分支可单步 |
| `OC` 分派表（41 条 名→wire 码） | 解释器顶部字面量表 | 直接写反汇编器 |
| `AL`/`TK` 载体表 + `decarrier` | 解释器内物化表 + 明文函数 | 复制出来即可脱壳全部字节码 blob |
| 字节码 blob 内部 | `[nregs u16][nparams u16][vararg u8][nups][upsrc…][nconst][常量明文…][S 表][ncode][W][四 varint 流]` 定长规整头 | 结构一眼可识别；常量区 = 用户字符串/数字**明文** |
| `MS` 字符串表 | `MS[k]=CHAR(码…)` 数值重建 | 抄码即还原全部元方法名/报错文案 |

致命链：**可见的载体表 → 脱壳规整字节码 → 明文常量 + 可见的 OC 表 →
完整反汇编**。三个缺点本质是同一条链的三个环节。

指纹侧约束（决定改造顺序）：32 条指纹测的是**脚手架轮廓**（模块表
227 字段、CPS 循环、原语槽、-128/×128 阶梯、SoA 写回、fetch 环、
`=function` 数量带……），其中 F4/F6/F11/F13/F14/F23 与「解释器可见
程度」耦合——**字节码与常量改造对指纹完全不可见，解释器改造有耦合**。
这决定了阶段顺序（先做指纹不可见的纯收益项）。

## 1. 指纹口径改版（P0 ✅ 2026-09-05：先改尺子，再改产品）

原则：**学结构 = 保留轮廓带；安全性也像 = 新增安全指纹**。

`tests/v15_fingerprint.py` 扩成双部分：

**A. 轮廓项（沿用 F1–F32，口径收紧为「同数量级带」，本就是带；个别与
安全冲突的项降级为参考项并标注）**——预期受影响项预先登记：
- F4（`=function(` 计数）：解释器 handler 体加密后会计数下降 → 降带宽
  或改测「脚手架 + 引导期函数总数（含 load 生成的）」
- F11（fetch 环）、F13（-128/×128 阶梯）、F14（SoA 写回）：属「可见
  骨架」，P3 保留 → 不动
- F23（`and N or M` 融合）：handler 体加密会减少 → 由脚手架侧补足或降带

**B. 安全项（新增，每阶段带攻击脚本验收）**：

| 项 | 判据 | 攻击脚本 |
|---|---|---|
| S1 常量不可见 | 脱壳后 blob 中源程序字符串/数字常量恢复数 = 0 | `tests/attack_constants.py`：复用输出内可见载体逻辑脱壳 → 提取 → 与源语料对照 |
| S2 字节码不规则 | 结构扫描器定不出节边界；blob 熵 ≥ 7.5 bit/byte；无固定偏移头 | `tests/attack_structure.py`：固定偏移/长度模式探测 |

| S4 自描述消除 | 输出中不存在完整 OC 表/完整 AL 表（可静态重建的映射条目 ≤ 阈值） | 并入 `attack_interp.py` |

**验收**：指纹脚本改版落地、基线复测（轮廓项 32/32 保持 + 安全项如实
记录当前 0/6——先亮红灯，逐阶段转绿）。

## 2. P1 常量加密 + 动态内联 ✅ 2026-09-05（致命缺点③，指纹零耦合，先做）

### P1 完成记录

落地（`vmgen/isa.rs` + `compiler.rs` + `template.rs` + `handlers/mkstr.rs`）：
1. **常量载荷密钥流化**：每函数头部新增 `ckseed u16`；常量项按
   LCG（KM/KC 每构建、mod 2²⁸）逐载荷字节加性掩码（`(x+k)%256`，
   5.1 无位运算可解）；常量节总长 `csl` 前缀 = 失步锚点 + 完整性
   陷阱（`p ~= pe → while true do end`）。
2. **数字去文本化**：type 2（ASCII 数字）废除 → type 4 **dyadic 对**：
   `v = ±m·2^k`（m ≤ 2⁵³-1 精确，k ∈ [-1074, 971]），双掩码 varint
   存储；parse 用 ×2/÷2 链重建 2^k（无 pow 依赖），乘回精确。
3. **短串动态内联**：≤5 字节字符串不进常量池——新增指令 **MkStr**
   （ISA 第 42 条）：字节打包进 b/c/d 操作数（b0+b1·256 / b2+b3·256 /
   b4+len·256），按 `(mk1·a + mk2) % 65536`（a = 目的寄存器）加性掩码，
   handler 用 % / FLOOR 拆字节 + CHAR 循环重建——操作数流里无明文。
4. **攻击脚本升级（诚实性）**：`vmstatic.parse_blob` 学会新布局
   （ckseed + csl + type3 明文长度 + type4 停走）；S2 判据改「定长头
   可识别且字段自洽」（完整行走已被掩码破坏，P2 才动头部）。

结果：S1 基线 8 语料全部转绿（常量恢复 0 命中；P0 时 96%~100%）；
S2/S3/S4 诚实保持红。门禁：204/204 + 405/405 + 5 种子回归 0 失败 +
轮廓指纹抽查 18/18 + 31 示例 32/32 + 双档运行一致 + cargo test 27 +
纯度 0 非 ASCII。
（余：长串分段乱序并入 P2 布局乱序；KM/KC 目前仍在解释器文本可见，
P3 随 parse 一起进加密层。）

改 `vmgen/compiler.rs`（常量序列化）+ `template.rs`（parse 常量段）：

1. **常量载荷密钥流化**：字符串/数字常量字节与构建密钥流（LCG 族，
   常数藏于脚手架数字槽，复用现有密钥流机制）逐字节 XOR 后入 blob；
   parse 读常量时同流还原。
2. **数字常量去文本化**：不再存 ASCII 数字串——存**拆分对**（如
   `a*131071+b` 或浮点双半字重组），parse 用算术重建，blob 无数字文本。
3. **短串动态内联**（≤ 阈值字节）：不进常量池——编译期把该常量的
   `LoadK` 换成运行时重建指令序列（CHAR 数值链 + 每构建拆分/变序），
   常量表里根本没有这条目。
4. **长串分段乱序**：切段 + 段序每构建洗牌存储，运行时拼回。
5. 常量段的**偏移/长度字段本身**并入 P2 的布局乱序（本阶段先加密载荷）。

**验收**：S1 攻击脚本恢复率 0；矩阵 204/204 + 预设 405/405 + 多种子
0 失败；轮廓指纹 32/32 不动（字节码对指纹不可见）；性能：解析期解密
开销 < 2×（语料实测）。

## 3. P2 字节码不规则化 ✅ 2026-09-05（致命缺点②，指纹零耦合）

### P2 完成记录

落地（`vmgen/isa.rs` + `compiler.rs` + `template.rs`）：
1. **布局描述符化（节化）**：函数 blob 不再是定长头 + 平行流——
   拆成 6 类节（HEAD/CKSEED/UPS/CONSTS/SLOTS/CODE）+ DECOY 诱饵节，
   每构建**随机乱序**拼接，节身份 = 每构建随机的 7 个 tag 字节
   （`section_tags`），所有计数字段（nregs/nparams/vararg/nups/nconst/
   csl/ns/ncode）全改 7-bit varint——固定偏移结构彻底消失。
2. **全 blob 位置掩码流**：载体编码前，整个函数 blob 叠一层
   `key = LCG(BM,BC)` 位置相关加性掩码；每函数种子
   `(blob_seed + fi·blob_step) % 2²⁸`（parse 收 `fi` 参数）。载体被破
   后内层仍是密文。
3. **假节**：每函数 0~2 个 8~48 字节诱饵节（种子派生垃圾），
   破坏「一个原型一个规整块」的假设。（假原型 = 整函数级诱饵，
   涉及原型索引重排，留后续。）
4. **指令流加噪**：`isa::unused_operands` 表标记每指令的闲置操作数，
   finish() 填充随机值——四条 SoA 流不再有零填充对齐特征。
5. 攻击脚本诚实更新：`vmstatic` 记录 P2 布局（tag 身份与掩码密钥
   都在解释器层 = S3/S4 域，blob 层攻击无法行走节结构）。

结果：S2 基线 8 语料全转绿（定长头可识别 0，blob 熵 4.55→7.31，
逼近载体字母表上限）；S1 保持绿；S3/S4 诚实红（待 P3）。
门禁：204/204 + 405/405 + 5 种子回归 0 失败 + 轮廓指纹抽查 18/18 +
31 示例 32/32 + 双档运行一致 + cargo test 27 + 纯度 0 非 ASCII。

1. **布局描述符化**：函数 blob 不再是固定字段序——每构建随机**节顺序**，
   头部只存一个（加密的）布局描述符，parse 先解描述符再按序读节。
   定长 `u16` 头字段全改 varint，彻底消灭「固定偏移结构」。
2. **全 blob 位置相关 XOR**：在载体编码之前，对整个函数 blob 叠一层
   `key[i] = f(i, 构建密钥)`——即使载体被破，内层仍不可读。
3. **假节/假原型**：种子派生的诱饵节（垃圾字节段）与假函数原型
   （解码即弃，或引入死校验），破坏「一个原型一个规整块」的假设。
4. **指令流加噪**：扩展现有 Nop 填充为「哑操作数 + 哑指令」混合填充，
   四操作数流的平行对齐外观被打散。
5. 解码方（parse）相应改写为描述符驱动的状态机（恰好与样本的
   状态机解码气味一致，轮廓加分）。

**验收**：S2 结构扫描器全失败 + 熵达标；全门禁绿；轮廓指纹保持。

### 增量⑰ 完成记录（2026-09-06，防静态加强第九轮，引导迷你 VM）

**背景**：R003 用「白名单算术折叠 + 路径约束传播」再次完整还原，
并留下两条极有价值的情报（其 Q2 回答）：
1. **256 类坍缩定理**：字节消费的线性钥匙流 `((a·x+c) mod 2²⁸) mod 256
   = (a·(x mod 256)+c) mod 256`——归纳得每个输出字节只依赖种子
   mod 256。我们全部 28 位 LCG 种子的有效熵其实只有 8 位（R001 当年
   穷举 256 钥匙不是巧合）。
2. **迷你 VM 反事实评估**：白名单折叠器覆盖不了操作码分派语义；
   间接访存 + 数据相关分支 + 自修改的组合自估 **3~6 倍**工作量，
   需要全新的指令格式提取 + 模拟工具。

**⑰-B 钥匙流全状态折叠消费**（定理整改）：所有 LCG 字节钥匙流
（常量池 / blob 两段掩码 / APH / TKD / HQ 碎片 / HBOOT 元流 / 脚手架
分块 XOR）的消费点改为四字节折叠：
`key = (s%256 + ⌊s/256⌋%256 + ⌊s/65536⌋%256 + ⌊s/2²⁴⌋) % 256`
（Rust `isa::fold_key` 与 Lua 镜像；v15 chunk handler 用
`bit32.extract` 变体）。256 类穷举捷径失效；未来运行时值混入也真正
有效（⑯-1 的前提修复）。

**⑰-A 引导迷你 VM**（主菜，攻击者自述的 3~6 倍区间）：
⑯ 的可见元解码器（钥匙流推导 + HBOOT 解掩码循环）整体改成一段
**小号自定义字节码程序**，由可见分派器执行：
- 15 指令寄存器机（R[0..7] + 内存 MM + 程序即数据表 MP）：
  `LDI/LDM/STM/LD/ST/MOV/ADD/SUB/MUL/DIV/MOD/JZ/JMP/STP/HALT`；
- **间接访存**：`LD/ST` 经寄存器内地址；`LDM/STM` 经程序内常数槽
  （双层 MP 解引用）；
- **自修改**：折叠除数 256 不落字面量——开机用 8 次重复加倍算出，
  `STP` 写回程序阵列的常数槽后才使用；
- **数据相关分支**：循环边界由寄存器运算 + `JZ` 相对跳转；
- 每构建：指令编号置换（1..15）、内存基址（输入/输出/暂存）随机、
  程序布局常数区随机；种子（含 ⑯-1 探针钥匙化项）经 MM[1] 喂入。
攻击者要拿 HBOOT 必须先：提取 ISA（读分派器）→ 写模拟器 → 跑通
自修改与间接访存——R003 自述这是其管线外的新工具类。

**⑰-D 作用域陷阱**（R003 Q6：其三次返工全因「名字匹配≠作用域
绑定」）：FC 入口机内加死作用域同名遮蔽诱饵（`do local u=... local
w=... local o=... end`，复用机内硬编码名，永不触达）。

**⑰-C 评估后缓行**：蜜罐碎片方案（第二条自洽假解码链）被 R003 的
引用普查能力（F44：按引用关系判死，不按长度/随机度）提前否决——
零引用的假碎片只增加分诊工作量、不构成误导；性价比低，缓行。

**附带修复**（多种子矩阵揪出）：

**动机**：㉗ 把可见探针点清零后，剩余的最大口子 = 「解码器 + 密文原型树

**落地（三刀）**：
1. **编译器基本块分割**（`compiler.rs::finish`）：leader = pc1 ∪ 跳转
   目标 ∪ 跳转后落点；噪声/散布之后位置定型时计算；`VmProgram::
   block_starts` 逐原型输出（children 0..、main 最后，与 FN 序一致）。
2. **BSS 按块编码 + 会话盐**：SALT = boot 期 `tostring({})` 31 进折叠
   （新表地址，每运行随机）；块钥匙种子 = `pseed + proto*pstep +

   推出块钥匙的材料**；跨运行钥匙全变。BSS 返回 `MPF, SALT`。
3. **RT 碎片按块即需即解**：整流解码器废除；`bdec(E, bi)` 解单块进帧
   私有窗口 `E.ww`（opcode）/`E.w0..w3`（操作数，按流槽序）+ 帧级块缓存

**安全语义**：任意时刻内存 = 密文块 + 已执行块的帧内缓存。文件级解码

自认的边界：「按页解码主要增加动态转储成本，攻击者仍可收集所有被执行
页」——本轮把成本从「一次插入」抬到「全程跟踪」）。

### 增量㉞ 完成记录（2026-09-16，自研压缩——一趟流水融合）

**背景**：用户点题「之前的压缩方法是找的吗，可以尝试自研」。不从既有方
案里挑，直接对 chunk handler 的生成代码做结构分析。

**自研发现**：handler 旧形态是两趟流水——第一趟把掩码词解成字节入字符
表、concat 成段串，第二趟对段串逐字节做 XOR 进输出表。而 XOR 钥匙 =
`(fold4(kv) + i) mod 256` **只随字节序号线性变化、无状态推进**（fold4 在
循环外只算一次）——两趟在数学上等价于趟，可融合：词解码位直接出
XOR 后字节，字节序号游标跨槽段连续。配套两个 Lua 语义压缩形态：
`string.byte(s, i, i+4)` 多返回值一次取 5 连字符（替代 5 个带偏移算术的
嵌套调用）；`string.char` 多参数整词 4 字节串一次入表。

**踩坑两枚（均已修复）**：
1. `string.char(c1,c2,c3,c4)` 返回**单个**串、不是 4 个值——多赋值展开
   `t[i],t[i+1],...=string.char(…)` 只写第一槽、余皆 nil（concat 报
   「invalid value (nil) at index 2」）。改整条追加 `t[#t+1]`。
2. 词粒度表的**索引截断只到词界**：`table.concat(t,nil,1,nw)` 会把尾部
   (4nw−blen) 字节 padding 泄漏进载体 → 后续段错位、解析期死循环。用
   **变体矩阵法**定位（5 个形态变体用环境变量临时固定，逐组合对拍，
   「bit32 提取 + 索引截断」组合复现）→ 词数粗截 + `string.sub` 字节精
   截两段法。

**保留的防御性质**：五变体（循环族/字节提取族/解掩加减/截断形态/词源形
态）仍正交组合、每 handler 名字/常量/形态唯一（⑫ 抗孪生函数识别不削
弱）；掩码钥匙仍无解码点字面量（增量⑩）。

**效果**：R016 409KB → **400KB**；自 ㉜ 起累计 443.9 → 400.1（**-9.9%**）。
诚实边界：体积大头仍是 ~137 个模块表 staging handler 的内联解码代码
（≈240KB），为拟态 + 变体多样性的设计产物；继续压缩需动 CHUNKS 链长/变
体密度等结构参数（权衡轮廓指纹与抗孪生识别），列待用户拍板。

**门禁**：166/166 + 360/360 + 多种子 0 + 轮廓 32/32（语料 & R016）+ 安全
5/5 + 钥匙 54 组 0 泄漏 + 同种子字节级确定。

### 增量㉒ 完成记录（2026-09-08，选项B·B-2，碎片即用即毁——原型加密集散）

**来源**：R007 攻击回合的教训——「干净运行 + 装配点/内存转储」之所以能
100% 还原，前提是 boot 后**平铺解码态原型表 `PF`（全部指令流 + 常量池）
永久常驻**：一次转储拿走整个程序。上节后续候选第 1 条（碎片即用即毁，
R006 壁垒①）本轮落地。

**机制**（三个动作，全在 v15 引导链内，零用户可见变化）：
1. **ENC 碎片（wire 207，加密 HQ 碎片）**：`PF = LS(BSS)()(...)(FN)`
   解析完成后立即执行——逐原型把五条流（W/SA/SB/SC/SD）用每原型独立
   LCG 钥匙流（种子 = `pseed + i*pstep`）做加性掩码；常量池：整数
   （`v % 1 == 0` 且 `|v| < 2^50`）加性掩码，其他有限小数走 Luau 最短
   往返 `tostring` → 逐字节掩码 → 解码端 `tonumber`，布尔/nil 折叠进
   掩码类型槽（0..5）；同时扫描 Closure 线码，把父子原型关系链成密文
   句柄表 `ep.k`。只返回树根 `MPF`，随后 **`PF = nil`**——平铺解码态
   全程序表在 boot 期即死亡。
2. **DDEC 碎片（wire 206，常驻解码器）**：工厂形态
   `function(PS,PT,KM,KC) return function(q, ...) end end`——钥匙在 boot
   期经钥匙碎片（KA/KB/KC/KM 查表）装配后注入闭包上游值，因此引导尾巴
   把钥匙表置 `nil` 也不影响后续解码。`newE` 每次调用
   `DDEC(pf, FLR, CHAR, UNP, TONUM)` 解出**全新**的流/常量表（帧私有），
   帧退出即成垃圾。
3. **原型持有去平表化**：`makefn(pf, ...)` 改收密文句柄；Closure handler
   `V[a+1] = makefn(E.k[b+1], V, ups, S)` 经当前帧的密文子原型图取子原型；
   入口 `run(MPF, ...)`。**闭包从此只捕获密文**——遍历所有活闭包也只能
   拿到密文原型。

**语义**：任意时刻内存 = 密文原型树 + 活帧的解码碎片（栈深 × 帧字节码）
+ 常驻可执行碎片（HW2/CT/CX/DDEC）。**完整解码态程序无处存在**——
「脱壳」（一次转储拿走全部字节码）概念终结，这是 R006 壁垒① 的字面落地。
攻击者要重建完整程序必须对 43 个加密分派点逐点动态插桩、逐帧收集——
而分派无单一钩点（⑲ 红利），收集成本与工具复杂度显著上升。

**Nop 自改写挪位**：F14/F27 指纹的 `ZW` 直写必须发生在编码前——从
`hfrag` 后挪进 boot `do` 块、ENC 调用之前（可见形态不变，轮廓 32/32 保持）。

**两个实现坑（记录在案）**：
- 加性掩码对**任意小数**不精确（`3.14159 + 2^28` 尾数溢出 → float32 级
  失真）——整数才走加性，其余数值走 `tostring`/`tonumber` 最短往返；
  编译期 `consts_mask_safe` 只把 NaN/inf 降级为常量池明文（流仍加密）。
- loadstring 碎片**没有词法作用域**——KA/KB/KC/KM 必须显式传参；DDEC
  常驻特性要求钥匙以 boot 期求值的数值注入闭包（查表在钥匙表被置 `nil`
  前完成）。

**开销**：每调用解码一帧（≈ 5×ncode 次 LCG + 常量重建）。fib(25)
（242,785 次调用）实测 4.13s → 4.22s（**+2%**）；全矩阵超时余量不变。

**测试**：新增 `tests/proto_enc_test.sh`（5 项，内嵌 run_tests.sh）：
模板形态（ENC/DDEC 接线/`PF = nil`/MPF 入口/makefn 密文句柄、平表引用
清零）+ HQ 碎片数 54（43 指令+4 重入+4 执行器+BSS+DDEC+ENC）+ 嵌套
闭包三种子等价 + 常量往返（小数/大整数/转义串/布尔）+ 深递归闭包计数器。

**诚实边界**：① 活帧内的解码流在帧存活期间仍可转储（= 任何调试器看任何
程序的等价物，单帧非全程序）；② 常驻可执行碎片（handler 本体）不变
（分派热路径，R007 已证明可从行为反推单片语义，但 43 片全量反推 + 无
钩点仍是工程墙）；③ 原型元数据（`upsrc`/`nparams`/`S` 槽表）明文保留
（结构骨架非逻辑，v1 范围）。动态全控对手仍可多次运行逐帧收集（R004
定律），抬的是成本不是绝对墙。

### 增量⑳ 完成记录（2026-09-07，选项B，激活值多因子化）

**背景**：⑱ 的激活折叠是线性 `h = h*31 + b`（mod 2²⁸）——代数结构可
折叠。若攻击者破了 AK 的 KT 查表装配，短字典激活值可被符号求解或字典
碰撞。⑳ 把激活哈希**去线性化 + 多因子化**，抬高这条路径的成本。

**机制（双因子非线性哈希）**：v15 = Luau，引导门直接用 `bit32`。每字节
三步混合：
```
h ^= b
h = lrotate(h, rot)
h ^= (h*mul + b) & 0xFFFFFFFF
```
两组独立参数并行折叠，末了各 `% 2²⁸`：
- 因子1：seed 0x811c9dc5 / rot 7 / mul 31 → ak1
- 因子2：seed 0x01000193 / rot 13 / mul 37 → ak2

扰动项翻倍进元钥匙流种子：
```
seed += (ak1 - AK1)*mix1 + (ak2 - AK2)*mix2   (mod 2²⁸)
```
正确激活 → 两项同时归零、HBOOT 正常解码；错/缺 → 任一项非零即元钥匙流
错位。**碰撞须同时满足两个非线性哈希**，比单因子线性折叠的代数攻击面
显著收窄。

**密钥装配**：AK1/AK2/mix1/mix2 全部经 KT 查表（`ke.key_expr`，锚
`#hqi`）装配，产物 0 字面量；种子常量经 `obf_num` 发射（FNV 常量不落
明文）。钥匙扫描 31 组（+BIND_AK2/BIND_MIX2）0 泄漏。

**镜像正确性**：Rust `activation_hash`（`u32::rotate_left` /
`wrapping_mul` / `wrapping_add`）与 Lua `bit32.bxor/lrotate/band` 逐字节
一致——同键三方核对（Rust / Python 参考 / Luau）+ 绑定门 10/10 实证
（正确钥匙跑通、错/缺钥匙引导层崩溃）。`h*mul + b` 在 Lua 侧 < 2³⁷，
double 精确，`band` 取 mod 2³²，与 Rust wrapping 语义完全对齐。

**影响面**：仅绑定（`--bind-key`）产物；未绑定输出字节级不变（⑳ 的
rng/key_expr 消耗全在 `bind_key.is_some()` 分支内）。

**诚实声明**：这是**成本抬升**，不是密码学保证——该 fold 仍非抗碰撞
哈希，激活值应有授权码级熵（长随机串）；⑲⑳ 叠加后静态攻击面 = 破 KT
查表装配 + 双非线性哈希反演，较⑱ 的线性单因子明显变陡。

**附带（S5 口径校准 → 安全指纹首次全绿）**：S5 一直红是**口径过时**，
不是防御缺失——P3 时代判据是明文 `["loadstring"]` + `debug.info` 配对，
P4 防御名全部运行时装配后明文字面配对必然失效（防御变强的副产品）。
按 F13 口径先例校准 `tests/attack/load_attack.py` 为**结构配对**：
- (a) 原生性探针 `<pcall>(function() return <f>(<x>, <y>) end)`
  （pcall 包裹双参调用 = `pcall(debug.info(loadstring, "s"))` 的
  运行时装配名形态）；
- (b) 静默陷阱 `if not <v> then while true do end end`（探针失败即挂起）。
两形状经 mangle/flatten/minify 不变，多种子实测恒 probe=1/trap=1；
无防御的输出不匹配 → 仍具区分力。**安全指纹首次 34/34 × 5/5 全绿**。

**门禁**：246/246 + 465/465 + 多种子 0 失败（含绑定 5 种子扫描）+ 绑定门
10/10 + 钥匙扫描 31 组 0 泄漏 + cargo test 27 + 未绑定输出字节级不变
+ **轮廓 34/34×32 + 安全 34/34×5/5**。

### 增量⑲ 完成记录（2026-09-07，选项B路线二，CPS 去中心化尾调用链 + 蹦床）

**背景**：R006 三壁垒之②「全局 hook 咽喉点消失」——中心
`while true do fetch dispatch end` 是攻击方单点挂钩即可追踪全部指令的
咽喉（其自动化工具的核心锚点）。⑲ 把它彻底拆掉。

**决定性平台事实（设计约束）**：Luau 官方已删除正确尾调用
（devforum 3307934：「Tail calls were removed from Luau... no plans to
revive」）；实测 ~20k 调用帧溢栈。纯尾链每指令积 1 帧——跑不了任意循环，
也扛不住深递归。**纯 CPS 尾链在目标方言不可行**，这是本轮最重要的侦察
结论（上一轮位置钥匙加密试错之后的第二次「平台定理」校准）。

**架构（预算有界尾链 + 蹦床）**：
- `pc` 迁入 `E.pc`；每条链最多走 `CHAIN_BUDGET=16` 条指令（`E.b` 预算，
  耗尽空返回、整链解开回落蹦床）；蹦床重置预算、轮转 4 个**加密重入碎片**
  （wire 301–304，形状=尾链附言、无操作码语义）从 `E.pc` 续跑。
- 每个非-Return handler 末尾接**多态尾链附言**（5 种语义等价形态 × 随机
  临时名 × 预算前缀 2 形）：`E.b-=1; if E.b==0 then return end;
  <fetch E.pc + HW2[(oc+AV)%256] 尾调用>`。跳转移位 `E.pc = b`。
- Return handler 置 `E.out/E.total/E.done` 后空返回；蹦床以
  `U(E.out, 1, E.total)` 统一出口。
- **Call 家族两相拆分**（深递归不溢栈的关键）：链相位（参数打包 →
  暂存 `E.cf/ca/cn/oa..od` → `E.callx=N; return` 解链）+ 执行器碎片
  （wire 305–308：浅层 `E.tp(fn(U(E.ca,1,E.cn)))` + 结果回写 + 尾链续跑）。
  调用点从此不在链深处，递归每层帧剖面回到旧设计量级。
- **蹦床内联进 makefn 闭包**（每层递归省 1 帧）；`newE` 前向声明解
  「newE 引用 makefn、闭包引用 newE」的循环依赖；E 构造移入 `newE`
  （其帧随返即销，run/闭包帧瘦身）。
- **选择性 prelude**：每 handler 只绑 body+附言 word-boundary 实际引用
  的 env（29 → 平均个位数），递归帧槽大头消除。

**可见面变化**：`run()`/makefn 闭包只剩 `while true do E.b=K; if
E.callx>0 then CX[..](E) else CT[(ti%4)+1](E) end; if E.done then
return ... end`——无 `W[pc]` 取指、无 `HW2` 触碰、无操作码比较。
F11 口径（可见 fetch 形状 ≥4）由 4–6 个 DF 死段诱饵恢复（真实取指已入密，
「哪个循环是真的」变成构造性死胡同）。

**递归深度实测**：旧设计贴线 `tail(5000)`；⑲ 后 8000 过、~10000 贴
Luau 原生栈限（每层 2 帧=闭包+执行器，已近理论下限）。语料需求 5000 ✓。

**攻击成本结构变化（对照 R006 工具链）**：
- 「挂钩中心循环追指令」→ 中心循环已不存在；蹦床循环无操作码语义，
  挂它只能看到「链重启/调用发生」事件流。
- 还原分派语义 → 需解 43 个加密 handler 的尾链附言（每构建多态）+
  4 重入碎片 + 4 执行器碎片；`HW2` 仍有 AV 每运行重键。
- 诚实声明：`loadstring` 装配咽喉与 ⑱ 前相同（持真钥匙真跑再挂钩子的
  运行时攻击面不变——那是运行时防护范畴）；⑲ 抬的是**静态/半自动还原
  分派语义**的成本，与 ⑱（无钥匙不可脱壳）正交叠加。

**门禁**：246/246 + 465/465 + 多种子 0 失败（含绑定 5 种子扫描）+ 轮廓

商业防护价值」。其结论：外层加壳/多层迷你 VM/折叠钥匙流已饱和且
无效；唯一质变投资 = 选项B（外部输入绑定 + CPS 去中心化尾调用链），
估算首次逆向 2~4 周、边际数小时~数天/样本、自动化基本不可行。用户
拍板路线一（输入绑定）。

**自举矛盾与设计**：混淆器编译期加密，但运行时输入编译期不可知——
唯一解是**激活值绑定**（授权绑定，不是任意业务输入绑定）：程序自带
激活语义，混淆器编译期就知道激活值 S；引导链在 K=hash(S) 下才解得开，
运行时读递送的激活值算 K'，对→跑通，错/缺→引导层垃圾崩溃。

**实现（最小侵入边界，吸取位置钥匙加密试错教训）**：上一轮曾试「操作
数流 + W 位置钥匙加密」，撞三处深层耦合（校验和折叠依赖未赋值的
cks、parse 是 loadstring 碎片看不见外层局部、错位操作数致深层分派
调 nil）后回退。本轮改混**元钥匙流种子**（HBOOT 门）——整条解码管
线（HBOOT→44 HQ 碎片→解析器）都挂在它下面，门一层即门全部：
`g = (meta_seed + (pb - fold31("[C]"))*probe_mix + (ak - AK)*bind_mix) % 2²⁸`
- `ak` = 第一个变长参数的 31 进折叠（引导部可见代码，`TYP` 守卫）；
- `AK = fold31(激活值)` 经 KT 查表装配（锚 #hqi），产物 0 字面量；
- 编译期掩码镜像不变（其种子是常数 meta_seed，扰动项运行时归零）；
- 未绑定路径零 rng 消耗——未绑定输出**字节级不变**（gen_examples
  全量重生成 0 diff 验证）。

**交付通道（实测关键发现）**：沙箱 Luau CLI 不转发命令行参数给
`...`、全局只读、无 io、无 loadfile、无 os.getenv——**唯一输入通道是
加载器显式变长参递送**。故生产交付模型：`loadstring(src)(key, ...)`
/ Roblox 加载器 / 包装函数调用；lua51 CLI 直接转发命令行参数。
脚手架 E 入口闭包加 `,...` 透传（`bind_passthrough` 开关）、VM 签名
`function(F1..Fn, ...)`、尾部把第 2+ 个变长参转发给程序本体
（`vargc = #vargs`）。

**死法**：错/缺钥匙 → 元钥匙流错位 → HBOOT 解出垃圾 → `loadstring`

## 回应 R018 攻击方报告 P0：运行期钥匙全族每运行化（增量㊵，2026-09-19）

攻击方报告建议把运行时值（BV）镜像进其重建模型的三处钥匙点
（`pbp_init`/`qh0`/`g`）。映射到我方发射面并做对称性审查：

1. **对称定理**：`g`（meta_seed_full）与 hb/hqi/HQ/MPM 掩码流都是
   **构建期掩码**——解密侧（metavm/HBOOT 运行期代码）必须精确复算构建期
   钥匙，任何每运行值混入都会让干净环境解密失败。因此这三处按字面照做
   = 产物自毁。`g` 上已有的 ㉛ 分裂乘积直参零和项（pb 探针 +
   环境探针）是构建期掩码线能承载的物理极限：它逼攻击者建模环境/钩子
   行为，但干净环境值构建期可知，静态重放该线仍可行。
2. **可行切片（已落地）**：块钥匙基 **RPK1..5（PS/PT/KM/KC/PB）与 BSS
   实参全部混入每运行必变的 AV**（新表地址 31 进折叠，boot 内前移计算）。
   消费两侧（BSS 运行期编码 / RT 运行期解码）都从 boot 拿同一运行期值，
   对称性天然成立。
3. **效果**：运行期阶段全部钥匙（AV 偏移基 + B-3 SALT + ㉚ 链终值）
   每运行不同——静态重放 BSS/RT 阶段中间态一次性，收集品作废；用户
   字节码三重运行期钥匙化，**只能执行获取**。
4. **诚实边界**：构建期掩码流（hb/hqi/HQ/MPM）依定理仍可按构建重放；
   重放得到的是 VM 内核（handler/RT/解析器），不是用户字节码——元解码器
   必须可见（⑮ 基底定理边界）。攻击链收益被压缩到「理解混淆器本身」，
   提取用户程序仍必须运行。

验证：冒烟 5 语料×3 种子 + 156/156 + 360/360 + multiseed 0 失败 +
防御审计 16/16（含 32/32、5/5、钥匙 0 泄漏）+ 字节级确定。
