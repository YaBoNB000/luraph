# 「看着像 + 安全性也像」总计划（学结构，不抄结构）

> 2026-09-05 立项。用户目标：**看着像**（轮廓、气味与 Luraph v15 同族）、
> **安全性也像**（攻击成本同量级）；**学结构不是一比一抄**——指纹从
> 「逐条对黄金数」降级为「轮廓带 + 安全项」，给安全改造让路。
> 同期用户指出三个致命缺点（本计划的直接驱动）：
> ① 虚拟机解释器完全明文暴露；② 字节码结构过于规整；③ 常量没做
> 动态内联/加密。

---

## 0. 现状事实核对（攻击链侦察结论）

当前 v15 输出对静态分析者是**自描述**的——复原整个 VM 不需要运行程序：

| 可见物 | 位置 | 攻击者拿到后能做什么 |
|---|---|---|
| 解释器全部逻辑 | 经 junk+mangle 后以**代码**嵌进脚手架 dh 数字槽跑者（strings/numbers/body/flatten 全关） | 直接读懂 fetch/dispatch/parse/载体解码；控制流未扁平化，逐分支可单步 |
| `OC` 分派表（41 条 名→wire 码） | 解释器顶部字面量表 | 直接写反汇编器 |
| `AL`/`TK` 载体表 + `decarrier` | 解释器内物化表 + 明文函数 | 复制出来即可脱壳全部字节码 blob |
| 字节码 blob 内部 | `[nregs u16][nparams u16][vararg u8][nups][upsrc…][nconst][常量明文…][S 表][ncode][W][四 varint 流]` 定长规整头 | 结构一眼可识别；常量区 = 用户字符串/数字**明文** |
| `MS` 字符串表 | `MS[k]=CHAR(码…)` 数值重建 | 抄码即还原全部元方法名/报错文案 |

致命链：**可见的载体表 → 脱壳规整字节码 → 明文常量 + 可见的 OC 表 →
完整反汇编**。三个缺点本质是同一条链的三个环节。

指纹侧约束（决定改造顺序）：32 条指纹测的是**脚手架轮廓**（模块表
227 字段、CPS 循环、原语槽、-128/×128 阶梯、SoA 写回、fetch 环、
`=function` 数量带……），其中 F4/F6/F11/F13/F14/F23 与「解释器可见
程度」耦合——**字节码与常量改造对指纹完全不可见，解释器改造有耦合**。
这决定了阶段顺序（先做指纹不可见的纯收益项）。

## 1. 指纹口径改版（P0：先改尺子，再改产品）

原则：**学结构 = 保留轮廓带；安全性也像 = 新增安全指纹**。

`tests/v15_fingerprint.py` 扩成双部分：

**A. 轮廓项（沿用 F1–F32，口径收紧为「同数量级带」，本就是带；个别与
安全冲突的项降级为参考项并标注）**——预期受影响项预先登记：
- F4（`=function(` 计数）：解释器 handler 体加密后会计数下降 → 降带宽
  或改测「脚手架 + 引导期函数总数（含 load 生成的）」
- F11（fetch 环）、F13（-128/×128 阶梯）、F14（SoA 写回）：属「可见
  骨架」，P3 保留 → 不动
- F23（`and N or M` 融合）：handler 体加密会减少 → 由脚手架侧补足或降带

**B. 安全项（新增，每阶段带攻击脚本验收）**：

| 项 | 判据 | 攻击脚本 |
|---|---|---|
| S1 常量不可见 | 脱壳后 blob 中源程序字符串/数字常量恢复数 = 0 | `tests/attack_constants.py`：复用输出内可见载体逻辑脱壳 → 提取 → 与源语料对照 |
| S2 字节码不规则 | 结构扫描器定不出节边界；blob 熵 ≥ 7.5 bit/byte；无固定偏移头 | `tests/attack_structure.py`：固定偏移/长度模式探测 |
| S3 指令语义不可见 | 输出文本中 handler 特征片段（报错文案骨架、指令模式串）命中 = 0 | `tests/attack_interp.py`：特征片段 grep + MS 表反解 |
| S4 自描述消除 | 输出中不存在完整 OC 表/完整 AL 表（可静态重建的映射条目 ≤ 阈值） | 并入 `attack_interp.py` |
| S5 动态加载防护 | 使用 `load` 处伴随原生性复检（hook → 陷阱） | 代码审读 + `tests/attack_hook.lua`（模拟 hook load 运行混淆产物，必须静默挂起/错轨，不得交出解释器） |
| S6 运行等价 | 全矩阵 + 多种子 + 双方言运行一致（门禁，不是指纹） | 既有脚本 |

**验收**：指纹脚本改版落地、基线复测（轮廓项 32/32 保持 + 安全项如实
记录当前 0/6——先亮红灯，逐阶段转绿）。

## 2. P1 常量加密 + 动态内联（致命缺点③，指纹零耦合，先做）

改 `vmgen/compiler.rs`（常量序列化）+ `template.rs`（parse 常量段）：

1. **常量载荷密钥流化**：字符串/数字常量字节与构建密钥流（LCG 族，
   常数藏于脚手架数字槽，复用现有密钥流机制）逐字节 XOR 后入 blob；
   parse 读常量时同流还原。
2. **数字常量去文本化**：不再存 ASCII 数字串——存**拆分对**（如
   `a*131071+b` 或浮点双半字重组），parse 用算术重建，blob 无数字文本。
3. **短串动态内联**（≤ 阈值字节）：不进常量池——编译期把该常量的
   `LoadK` 换成运行时重建指令序列（CHAR 数值链 + 每构建拆分/变序），
   常量表里根本没有这条目。
4. **长串分段乱序**：切段 + 段序每构建洗牌存储，运行时拼回。
5. 常量段的**偏移/长度字段本身**并入 P2 的布局乱序（本阶段先加密载荷）。

**验收**：S1 攻击脚本恢复率 0；矩阵 204/204 + 预设 405/405 + 多种子
0 失败；轮廓指纹 32/32 不动（字节码对指纹不可见）；性能：解析期解密
开销 < 2×（语料实测）。

## 3. P2 字节码不规则化（致命缺点②，指纹零耦合）

1. **布局描述符化**：函数 blob 不再是固定字段序——每构建随机**节顺序**，
   头部只存一个（加密的）布局描述符，parse 先解描述符再按序读节。
   定长 `u16` 头字段全改 varint，彻底消灭「固定偏移结构」。
2. **全 blob 位置相关 XOR**：在载体编码之前，对整个函数 blob 叠一层
   `key[i] = f(i, 构建密钥)`——即使载体被破，内层仍不可读。
3. **假节/假原型**：种子派生的诱饵节（垃圾字节段）与假函数原型
   （解码即弃，或引入死校验），破坏「一个原型一个规整块」的假设。
4. **指令流加噪**：扩展现有 Nop 填充为「哑操作数 + 哑指令」混合填充，
   四操作数流的平行对齐外观被打散。
5. 解码方（parse）相应改写为描述符驱动的状态机（恰好与样本的
   状态机解码气味一致，轮廓加分）。

**验收**：S2 结构扫描器全失败 + 熵达标；全门禁绿；轮廓指纹保持。

## 4. P3 解释器分层保护（致命缺点①，指纹耦合，最后做）

思路：**可见骨架 + 加密语义**——轮廓靠骨架撑，安全靠语义层锁。

1. **拆两层**：
   - *可见骨架*（保留指纹形状）：fetch 环（F11）、varint 阶梯
     （F13 的 -128/×128）、自修改写回（F14）、状态元组解包、
     parse 状态机外形——但全部过 **flatten + junk + 数值混淆
     （指纹特征数白名单豁免）**，读起来是样本那种难跟的状态机，
     不是现在这种直白嵌套树。
   - *加密语义*：H 分派表的 **41 个 handler 体**不再以代码出现——
     打碎成加密片段藏进模块表数字槽（与诱饵槽同族，F9 轮廓带内），
     引导期逐片段校验 → 拼接 → `load()` 建表。
2. **OC 表运行时生长**：输出里不再物化 41 条完整映射；引导机按
   密钥流逐条填 `OC`（静态看只剩空表/半表）。
3. **载体表去物化**：`AL`/`TK` 不再整表物化——按密钥流计算
   （保留样本气味的少量明面条目作诱饵）。
4. **动态加载防护闭环**（呼应建议3/建议2 既有机制）：`load` 调用前
   复检原生性（`debug.info` 判 `[C]`）、调用后行为探针校验；
   被 hook 即静默陷阱。`tests/attack_hook.lua` 做攻防回归。
5. **5.1 档（`--vm` 非 v15）**：本阶段只改 v15 档；`--vm` 档解释器
   已走全管线（含 strings/flatten），单列后续评估。

**验收**：S3/S4/S5 攻击脚本全失效；轮廓项在改版口径内达带；
全门禁绿；`load` 路径在 Luau 0.735 + Roblox 语义可用（v15 档本就
Luau-only）。

## 5. 顺序与理由

```
P0 指纹口径改版（先改尺子：亮出安全红灯 + 给 P3 预留口径）
 → P1 常量（指纹零耦合，纯收益，掐断攻击链最末端）
 → P2 字节码不规则（指纹零耦合，掐断中段）
 → P3 解释器分层（指纹耦合最大，此时字节码/常量已不可读，风险集中可控）
```
每阶段走强制工作流：全语料双解释器对比 → 204 矩阵 → 405 预设 →
多种子（改 vmgen 必跑）→ 攻击脚本验收 → md 四处同步 → commit+push。

## 6. 风险登记

| 风险 | 对策 |
|---|---|
| P3 加密 handler 后指纹轮廓项掉出带 | P0 已改版口径 + 白名单；掉带即调带并在日志留痕 |
| `load` 被宿主限制（沙箱环境） | v15 档目标就是 Luau/Roblox（load 可用）；失败路径回退为「内置微型求值状态机」（样本气味更浓，备选） |
| 解析期解密拖慢启动 | 预算：语料级启动 < 2× 现状；超支则密钥流改分块查表 |
| 载体去物化破坏 F8/F16 等 blob 轮廓 | 保留样本气味的可见载体外壳，仅换内层 |

## 7. 完成定义（DoD）

1. 安全指纹 S1–S5 全绿（对应攻击脚本全部失效），S6 门禁恒绿；
2. 轮廓指纹在改版口径内达带，输出与样本「同气味」人工复核通过；
3. 三个致命缺点逐一闭环：解释器语义静态不可得、字节码无规整结构、
   常量零恢复；
4. 204/204 + 405/405 + 5 种子回归 0 失败 + 纯度 0 非 ASCII 保持。
