## 增量㉔：两条路径的根治

### ㉔-1 守卫结果钥匙化（反「补标志」）
loadstring 原生性探测不再有布尔标志与死循环 oracle（两者都是可补丁目标）：
探测结果直接折进元钥匙流——干净环境恒零项；探测失败/被钩换源 → 钥匙流
污染 → 引导解码出垃圾 → 错钥静默死亡。补标志没有目标可打。

### ㉔-2 环境值绑定（反「哑桩」）
㉑ 只绑目标 API 的**存在性**；本轮把目标运行时的**值**揉进元钥匙流：
引导期用每构建随机参数调用 `Vector3.new(a1,a2,a3)`/`Vector2.new(a4,a5)`，
对返回对象的 `.X/.Y/.Z` 分量做每构建随机系数的线性折叠（整数精确算术，
float32 分量存小整数无损）。哑桩折出垃圾值 → 钥匙流污染 → 错钥死亡。
桩必须**忠实实现构造语义**（按参数回传分量）才能过关。
诚实边界：受控沙箱若完整仿真这些 API 仍能通过（R004 定律）——抬的是
「任意桩」到「忠实仿真」的成本，不是绝对墙。
