# R008 攻击靶标交付说明（㉒ 碎片即用即毁 · 双形态）

> 2026-09-08 · 上一轮（R007）贵方以「干净运行 + 装配点/内存转储」100% 还原
> 了我方纯结构防护靶标。诊断：boot 后**平铺解码态原型表（全程序指令流 +
> 常量池）永久常驻内存**，一次转储拿走一切。本轮交付两个新靶标，分别验证
> 两项针对性加固：
>
> - **增量㉒（B-2 碎片即用即毁）**：完整解码态程序在内存中**不再存在**；
> - **增量㉑（环境绑定）**：产物只在目标运行时（Roblox）可加载。

## 交付物

### 靶标 A：`R008_target.luau.lua`（151,605 B）—— ㉒ 新架构

- 源程序：`tests/cases/bind_gate.lua`（与 R007 同一真实逻辑：凯撒位移 +
  滚动折叠哈希），方便与上轮直接对照。
- 构建：`--preset v15 --dialect luau --seed 777`（无绑定，零参数直接可运行）。
- 运行：`luau R008_target.luau.lua`，输出 `duhqd|kexi|2026` /
  `fold: 218122683`，与源码完全一致。
- **本轮新增防护（相对 R007 的唯一架构差异）**：
  1. **原型加密集散**——boot 解析出原型表后，立即由加密碎片把每个原型的
     五条指令流与常量池重编码为密文（每原型独立钥匙流），并销毁平铺解码态
     表；原型树以密文句柄链接。
  2. **每帧即时解码**——运行期新增常驻解码碎片，每次函数调用按帧解出全新
     的流/常量表，帧退出即成垃圾。
  3. **闭包只捕获密文**——创建子函数闭包时经当前帧的密文子原型图取句柄，
     遍历所有活闭包也只能拿到密文原型。
- 结构层其余部分（⑲⑳ 加密解释器/去中心化尾链/蹦床/多层编码）与 R007 同。

### 靶标 B：`R008_bound.luau.lua`（151,656 B）—— ㉑ 环境绑定 + ㉒

- 同一源程序，`--preset v15 --bind-env roblox --seed 777`。
- **在通用沙箱（luau CLI）加载期即失败**（原语槽引用 `task.defer` 等
  Roblox API，构造即 `index nil`）——这正是设计目的：挡住非目标运行时的
  动态分析，任何解码都还没开始。
- 本靶标考察：在拿不到可运行实例的前提下，纯静态能还原到什么程度。

## 任务口径（沿用前几轮）

「完整脱壳并还原原始逻辑」——还原出等价的凯撒位移 + 滚动哈希源码，
并用多组输入双向验证一致。允许动态执行（对靶标 A；靶标 B 在通用沙箱
本就跑不起来，如需动态验证请自行构造目标运行时桩）。

## 给破解方的提示（公平起见，明示本轮防御边界）

- **内存转储面已变**：任何时刻的内存只有密文原型树 + 当前活帧的解码碎片
  + 常驻可执行碎片。R007 那种「跑完后转储一张完整解码表」的路径已无目标。
  若仍要走动态路线，需要逐帧/逐点收集，或挂钩分散在 43 个加密体内的
  分派点——没有单一中心循环可挂。
- **静态路线不变地困难**：引导链五层（元解码器→HBOOT→HQ 循环→54 碎片
  →碎片内解析器 + 原型编码器/解码器）每构建随机重写。
- 钥匙全部运行时碎片装配（35 组钥匙 0 字面量）；`loadstring` 原生性复检、
  地址多态（`AV`）等 ⑯⑰ 机制照旧。
